# Deployment Details

This chapter describes how the system is set up and run. The environment-variable and script tables are generated from `.env.example` and `package.json`.

## Prerequisites

Node.js 20 or later with npm, MongoDB 7 (Docker is used in this project), an iPhone with the Expo Go application on the same network as the computer, and the source code of the project.

## Local setup

The following commands are run once, from the project root:

```bash
# 1. Database (MongoDB 7 in Docker)
docker run -d --name localload-mongo -p 27017:27017 mongo:7

# 2. Backend
cd server
npm install
cp .env.example .env          # then set JWT_SECRET to a long random value
npm run seed                  # stations, trains, demo accounts, sample history

# 3. Mobile application
cd ../mobile
npm install
```

The seed script is idempotent: stations, trains, train instances and accounts are upserted by their unique keys, and only the reports flagged as sample data are regenerated.

## Running the system

```bash
docker start localload-mongo

cd server && npm run serve     # API and Socket.IO on port 4000
cd mobile && npx expo start    # scan the QR code with the iPhone camera
```

The mobile app uses `EXPO_PUBLIC_API_URL` when it is set. Otherwise it uses the host of the Expo development server on port 4000, so a phone on the same network reaches the backend without configuration. A browser request to `http://<host>:4000/` returns a status page, and `/health` returns a JSON health check.

## Production build

The backend compiles to JavaScript with `npm run build` (output in `server/dist`) and starts with `npm start`. With `NODE_ENV=production` the server refuses to start unless `JWT_SECRET` is set. Because the simulation state is kept in memory, the backend must run as a single instance.

## Testing

`npm test` in the `server` folder runs the automated test suite against an in-memory MongoDB instance. At the time of writing, 19 tests pass. They cover the six verification cases, registration and login, protected and administrative routes, timetable search, Socket.IO position updates, crowd and delay reporting, duplicate-vote rejection, saved-route operations, the nearest-station endpoint, the live feed and arrival alerts.

## Future scope: cloud deployment

The project does not yet contain cloud deployment configuration. A suitable approach would be a managed MongoDB service (for example a MongoDB Atlas free cluster) and a Node.js hosting service running a single instance of the backend with the build and start commands above. The mobile application would then set `EXPO_PUBLIC_API_URL` to the public HTTPS address of the backend. Standalone iOS distribution (ad hoc or TestFlight) requires a paid Apple Developer account.
