# LocalLoad project report (docs-as-code)

The project report is written in Markdown in this folder and built into a **Word document**:

```
docs/report/output/report.docx
```

Open it in Microsoft Word (or LibreOffice) to add screenshots and make final edits. When Word asks *"This document contains fields that may refer to other files. Update the fields?"*, answer **Yes**: this fills the table of contents with page numbers (or right-click the table of contents and choose **Update Field**).

> Edits made directly in `report.docx` are **not** copied back into the Markdown. Make text changes in the `.md` files so they survive the next rebuild. Keep a separate copy of the `.docx` for screenshots (for example `report-final.docx`), or add screenshots as images in `03-proposed-solution.md` (see "Adding screenshots" below).

## Layout

| Path | Contents |
|---|---|
| `metadata.yaml` | Title, author lines, institution, date, and build settings (`toc`, `toc-depth`, `number-sections`) |
| `01-…md` to `14-…md` | One file per chapter, combined in file-name order |
| `diagrams/*.mmd` | Mermaid sources of every diagram (edit these, never only the PNG) |
| `diagrams/png/*.png` | Rendered diagrams (generated) |
| `reference.docx` | Word style template (generated by `scripts/report/make_reference_docx.py`) |
| `output/report.docx` | The finished report (generated) |

## What is generated from the code

`scripts/report/generate.mjs` rewrites these parts on every build:

| Part | Source |
|---|---|
| Chapter 10, Technology Stack (whole file) | `server/package.json`, `mobile/package.json` and installed versions in `node_modules`. Purposes come from the `PURPOSE` map in the script; a new dependency without a purpose fails the build. |
| Chapter 11, REST API table | `server/src/routes/index.ts` |
| Chapter 12, ER diagram (`diagrams/er-diagram.mmd`) and collection tables | `server/src/models/*.ts` |
| Chapter 13, code listings | Functions and classes named in `<!-- SNIPPET: file#Symbol -->` markers |
| Chapter 14, environment-variable and npm-script tables | `server/.env.example`, `mobile/.env.example`, both `package.json` files |

Generated content sits between `<!-- AUTO:name -->` / `<!-- /AUTO:name -->` or `<!-- SNIPPET: … -->` / `<!-- /SNIPPET -->` markers. Text outside the markers is yours and is never changed. To add a code listing, write the empty marker pair, for example:

```markdown
<!-- SNIPPET: server/src/services/status.ts#statusesFor -->
<!-- /SNIPPET -->
```

`Class.method` also works, e.g. `server/src/simulation/engine.ts#SimulationEngine.tick`.

## Tools to install (Ubuntu / Debian Linux)

| Tool | Install | Used for |
|---|---|---|
| Pandoc 3.x | `sudo apt install pandoc`, or the `.deb` from <https://github.com/jgm/pandoc/releases> | Markdown → Word |
| Python 3 | already part of Ubuntu (`python3`) | Building the Word style template (standard library only) |
| Node.js 20+ | already used by the project | Running the generator |
| mermaid-cli | `npm --prefix scripts/report install` (installs into `scripts/report/node_modules`) | Rendering diagrams |
| Google Chrome or Chromium | already installed; detected automatically | Browser used by mermaid-cli |

No LaTeX installation is needed, because the output is a Word document. If you also want a PDF, open `report.docx` in Word and use *Save as PDF*, or run `soffice --headless --convert-to pdf docs/report/output/report.docx`.

If no Chrome or Chromium is installed, install mermaid-cli without `PUPPETEER_SKIP_DOWNLOAD` so that puppeteer downloads its own browser, or set `PUPPETEER_EXECUTABLE_PATH` to a browser binary.

## Rebuilding

From the project root:

```bash
npm --prefix scripts/report install   # first time only
scripts/build_report.sh
```

The script:
1. regenerates the code-derived parts (`node scripts/report/generate.mjs`),
2. renders every `diagrams/*.mmd` to `diagrams/png/*.png` with mermaid-cli,
3. builds `reference.docx` (A4, 1-inch margins, Times New Roman 12 pt, page numbers, each chapter on a new page, gridded tables, 9 pt code),
4. runs pandoc to combine `metadata.yaml` and all 14 chapters into `output/report.docx` with a cover page, table of contents and numbered sections, then post-processes it.

Supporting files in `scripts/report/`:

| File | Role |
|---|---|
| `generate.mjs` | Regenerates the code-derived parts |
| `make_reference_docx.py` | Builds the Word style template |
| `number-headings.lua` | Pandoc filter that numbers headings (1, 1.1, …). Used instead of `--number-sections`, which pandoc 2.9 (Ubuntu's apt version) ignores for Word output |
| `finalize_docx.py` | Pre-fills the table of contents, tells Word to update fields on open, and fixes element order so the file passes Office Open XML schema validation |
| `ooxml.py` | Shared helper that puts Word XML elements in schema order |

Tested with pandoc 2.9.2.1. Newer pandoc 3.x versions work the same way.

It stops with an error message if any step fails: a missing tool, a missing marker or symbol, a Mermaid syntax error, a missing image, or a pandoc warning.

## Adding screenshots

Chapter 3 contains `[TODO: insert screenshot – …]` placeholders. You can do either of the following:

- **In Markdown (survives rebuilds):** save screenshots in `docs/report/screenshots/` and replace each placeholder with `![Home screen](screenshots/home.png){height=4in}`, then rebuild.
- **In Word:** replace the placeholders in a copy of `report.docx`. Remember that a rebuild overwrites `output/report.docx`.

## Keeping it in sync

Use the `/update-report` command in Claude Code, which compares the code with the report, updates outdated sections (keeping your wording), regenerates the automatic parts and rebuilds the document. You can also run `scripts/build_report.sh` after any change to dependencies, models, routes, `.env.example` files or the code shown in Chapter 13.
